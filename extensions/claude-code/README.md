Claude Code is an experimental provider that uses the external CLI login, with a setup panel and no in-app OAuth flow.

It is on by default; turn it off with `claude-code` in `extensions.disable`. Existing Anthropic models and the default model are unchanged.

Install the CLI with `npm install -g @anthropic-ai/claude-code`, then run `claude auth login` in a terminal. Open **Claude Code setup…** in the command palette and refresh status. Select a Claude Code model in the existing model picker once the CLI reports a login. Login/logout remain external (`claude auth logout`); refresh after changing them. Successful status checks also refresh the browser's model cache, so login/logout updates the picker without a page reload. Unreadable CLI status is reported as an unconfirmed login by upstream. Status action failures have a retry state.

The dependency is `earendil-works/pi-claude-code` at immutable commit `70abb65186592ca788b29b3db22c3160d629c41f`. Its source-only TypeScript package is loaded by Ultimate's existing Vite server-facet loader (not a direct Node import from node_modules). We reuse its provider, status/environment helpers, process cleanup, streaming transport and billing guard. The auth adaptation removes its throwing OAuth login function while retaining subscription metadata and ambient CLI auth. The selectable `claude-sonnet-5` model does not advertise thinking `off`: this pinned transport sends `disabled`, which the native Sonnet route rejects instead of accepting as `between_tools`. Its static and discovered metadata exclude `off`; Pi clamps unsupported levels to a supported level. Other models are unchanged. Tool ids from other providers (Codex: `call_…|fc_…`) are made valid for Anthropic's `^[a-zA-Z0-9_-]+$` before each request (`tool-ids.ts`); otherwise no request-body or transport rewrite is applied. No credentials are read, copied or logged by this extension. Status responses expose only availability, login, subscription and plan, not account identity or raw CLI output.

`PI_CLAUDE_CODE_COMMAND` selects the CLI executable; `PI_CLAUDE_CODE_CONFIG_DIR` selects its config directory. Upstream also supports provider-scoped environment settings; the panel uses the same environment remembered by its auth checks. Facet replacement keeps the provider registered continuously; disabling or removing the extension unregisters it without killing an in-flight request. The provider and its transport are a process-local host resource retained across facet reloads. On host shutdown, warm CLI cleanup waits for active streams to settle without blocking harness suspension: the harness signal interrupts requests, and durable reopening replays the unfinished request. A browser refresh only reconnects its event subscription; a setup status refresh checks auth/model availability, not stream ownership. User cancellation still aborts the request and is not replayed on reopening. Captured provider registrations use the same tracked stream wrappers across reloads and reject new requests once host cleanup begins. No new retry classification is added: an unexpected SIGKILL is not reclassified as a retryable lifecycle interruption.

Browser refresh, facet reload and host restart are distinct. Landing files can invalidate a facet through its dependency/import graph even when `extensions/claude-code/server.ts` itself did not change; this replacement can occur immediately after landing, before an explicit restart. Supervised swaps call `release()` to suspend the harness before extension cleanup, whereas ordinary `close()` cleans up extensions first. Tests exercise both shutdown orders.

This is experimental and depends on Claude Code's protocol and account limits. Subscription coverage is not guaranteed. Displayed costs are list-price accounting, not your bill. Upstream rejects conflicting API/backend overrides and stops further requests when usage-credit overage is reported, but the first response may already be charged. This extension does not enable `PI_CLAUDE_CODE_ALLOW_USAGE_CREDITS` or alter the guard. Read [upstream documentation](https://github.com/earendil-works/pi-claude-code) before using it.

Verification: `pnpm check`, `pnpm test:e2e` (`test/e2e/claude-code.test.ts`). The focused tests use a temporary fake CLI and isolated real server/harness to exercise provider availability, subscription accounting, status refresh, browser event reconnect, active source reload, durable close/reopen, supervised release/close/reopen, disable, missing CLI, unreadable auth status, user cancellation, permanent failure and worker cleanup without paid model requests.

The pinned upstream transcript builds tool-use/result frames from Pi's ids directly, including its native replay carrier. Both `stream` and `streamSimple` therefore pass upstream a copy of the context in which every invalid id, in tool calls, tool results and the carrier's `tool_use` blocks and projection, is replaced by its sanitized prefix plus a hash of the original. Valid ids are unchanged; replacements are rehashed on collision, so ids that sanitize alike or equal an existing valid id stay distinct. The mapping depends only on the transcript, so replays and reopened conversations send the same ids, and a mapped carrier still matches its message, so signed thinking is replayed. Stored history is not changed. `test/claude-code-tool-ids.test.ts` covers the mapping; the e2e test sends mixed Codex/Claude Code histories through a fake CLI that rejects invalid or unpaired ids like the API.
